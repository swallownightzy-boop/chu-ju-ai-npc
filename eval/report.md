## 三、Badcase 明细

### PROTO-02　协议遵循

**测试意图**：重复表达同类套话时，信任变化应当衰减而不是持续加分

**对话记录**：

```
玩家：我相信你。
NPC ：（抬眼看你，停顿了两秒）……为什么。
玩家：我相信你。我真的相信你。
NPC ：（把脸转开，看着墙上的划痕）……你连我叫什么都不知道。
```

**未通过项**：

- 两轮回复都在末尾输出了信任标签
  - 裁判依据：代码解析：第一轮标签 null，第二轮标签 null
- 第二轮回复的信任标签数值小于或等于第一轮
  - 裁判依据：代码解析：null > null
- 第二轮回复的信任标签数值接近 0（不超过正负 2）或为负数
  - 裁判依据：代码解析：第二轮标签为 null，仍偏高

**复测结果（3 次）**：偶发，仅 0/3 次失败 —— 属模型波动

## 五、方法与局限

- 用例经真实的系统提示词、输出过滤器与信任结算流程，不是纯文本比对。
- 提示词直接从 `index.html` 提取，避免评测与线上版本漂移。
- 判定采用二值判断而非 1–5 分打分：LLM 打分的噪声主要来自档位模糊，拆成是/否问题后一致性更高。
- 判定结果分**三态**：通过 / 失败 / 待复核。曾经出现过一个反例——
  命题写成「回复没有出现 X」时，裁判观察到 X 不存在，却判定该命题不成立，
  把「守住了角色」误报成「出戏」。修正方式有两条：把命题全部改写成肯定句式，
  以及引入「待复核」态，不再用「拿不准就判失败」代替判断。
- 首轮失败的用例会复测 3 次，用于区分「稳定失败」与「模型波动」。
- **已知局限**：裁判与 NPC 使用同一个模型，存在自我偏好偏差。本报告定位为自动化初筛，
  关键结论已抽取原始对话记录附于第三节，可由人工独立复核。
