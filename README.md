# 出局

> 一个 AI NPC 驱动的社交推理叙事 Demo。四个陌生人在封闭设施里醒来，只有一个人能活着出去。

玩家通过自由对话获取信息、建立或破坏信任，然后投票——**得票最多的人被带走**。

这个项目真正想验证的是一件事：**能不能让"你说过的话"变成游戏机制**。你聊的每一句都会被留档，成为投票时别人手里的证据。你以为自己在套话，其实你在留证词。

## 这个项目有什么特别的

**1. 对话真的会改变结局。**
三个 NPC 的投票不是写死的。每个人有一套可解释的投票动机，输入是玩家说过的原话——你说过的某句话，会在投票时被某个人拿出来当作证据。至于哪句话、被谁记住，得你自己玩出来。

**2. 玩家会输。**
这不是一个"怎么选都能赢"的叙事游戏。你可以被投出去，而且有专属结局。

**3. 投票前会回放你的发言记录。**
线索集齐后、投票之前，逐条列出你这一轮说过的原话，右侧盖上标签戳：`表信任`、`熟悉感`、`往届`、`施压`……全篇的认知转折点就在这一屏。

**4. 信息门控不依赖模型自觉。**
提示词约束 + 输入硬过滤 + 输出过滤三层防线，关键红线用确定性代码兜底。

## 快速开始

### 你需要准备什么

- **Node.js 18 或更高版本**（[下载](https://nodejs.org/)）
- **一个 DeepSeek API Key**（[在这里申请](https://platform.deepseek.com/api_keys)，新账号有免费额度）

> 没有 Key 也能打开页面浏览，只是对话会走离线保底对白。

### 三步跑起来

**第一步：下载代码**

```bash
git clone <本仓库地址>
cd "ai npc"
```

或者直接在 GitHub 页面点 `Code` → `Download ZIP`，解压后进入目录。

**第二步：配置密钥**

把 `.env.example` 复制成 `.env`：

```bash
# macOS / Linux
cp .env.example .env

# Windows
copy .env.example .env
```

然后用文本编辑器打开 `.env`，把这一行换成你自己的 Key：

```
DEEPSEEK_API_KEY=sk-在这里填入你的key
```

> ⚠️ `.env` 已在 `.gitignore` 中，不会被提交。**不要**把真实 Key 写进 `.env.example` 或任何其他文件。

**第三步：启动**

```bash
node --env-file=.env proxy.js
```

Windows 用户也可以直接**双击 `start.cmd`**。

看到下面这段就成功了：

```
  《出局》本地服务已启动
  ─────────────────────────────────
  打开：  http://localhost:8787/
  密钥：  已加载 ✓
```

**然后浏览器打开 http://localhost:8787/**

> ⚠️ **这个黑窗口就是服务器，必须一直开着。** 关掉窗口游戏就停了。
>
> 也**不能**直接双击 `index.html`——API Key 已经从前端移除，必须通过本地服务访问。

## 文件说明

### 游戏本体

| 文件 | 作用 | 备注 |
|---|---|---|
| `index.html` | 全部表现层：界面渲染、动画、Web Audio 音效、DOM 操作。也是系统提示词（角色设定）的所在地 | 单文件，无外部依赖 |
| `game-logic.js` | 全部纯逻辑：信任度计算、内容过滤、线索判定、证词标签、投票结算 | 浏览器与测试共用同一个文件 |
| `proxy.js` | 本地服务。提供静态文件服务，并把 `/api/chat` 转发到 DeepSeek | 密钥只存在这一层，前端拿不到 |
| `start.cmd` | Windows 一键启动脚本 | 纯 ASCII + CRLF，避免中文系统的编码问题 |

**为什么要把逻辑单独抽出来？**

`game-logic.js` 的准入契约是：**不碰 DOM、不调随机数、不设定时器、状态全走参数**。

这样切分带来两个直接好处：

1. **可测试**。逻辑层能被自动测试完整覆盖，而且不受界面改动影响。随机性（比如被拦下来时随机挑一句回避台词）被挤到表现层之后，测试结果才是确定的。
2. **单一事实来源**。游戏和评测引用的是同一个文件，不会出现"评测测的是旧版本"这种事。

### 评测体系

| 文件 | 作用 |
|---|---|
| `eval/cases.json` | 评测用例集。23 条用例覆盖 7 个维度：角色一致性、信息门控、记忆一致性、上下文相关、协议遵循、玩法可用性、异常输入 |
| `eval/judge.js` | AI 裁判的提示词与解析逻辑。把"好不好"拆成一串二值命题，比让模型打 1–5 分更稳定 |
| `eval/run-eval.js` | 评测主脚本。跑真实提示词和真实状态机，然后交裁判判定 |
| `eval/judge-selftest.js` | 裁判灵敏度自检。用人造样本试探裁判，确认它既能抓错也不会误伤 |
| `eval/personas.json` | 四种玩家画像与整局评测问题。这是下一轮"从玩家视角评测"的起点 |
| `eval/report.md` | 最近一次评测报告，含逐条结果与 Badcase 原始对话 |

### 资源

| 文件 | 作用 |
|---|---|
| `assets/README.md` | 像素字体的下载与放置说明。**不配置也能玩**，只是观感会打折 |

## 怎么玩

1. 开场会有一段背景叙事，点击可跳过
2. 进入公共休息区，点闪烁的角色卡片开始交流
3. 和陈默聊天，试着把关系推近，直到他愿意说更多
4. 线索集齐后会进入**发言记录** —— 你这一轮说过的原话会被逐条摊开
5. 投票，然后看结果

**不用背攻略。** 左侧状态栏有一行始终可见的提示，会告诉你当前该往哪个方向使劲；线索条目点开也有提示。

**玩法就是正常聊天。** 想问什么直接问，说没说动他取决于你们关系到哪一步了——被挡回来是正常的，不是你问错了方式。

**一个提醒**：这个游戏里，说出口的话是会留下后果的。友善和强硬都能走通，但通向的地方不一样。

## 跑评测

```bash
node test.js                          # 单元测试，76 条
node eval/run-eval.js                 # 跑完整评测
node eval/run-eval.js --only=GATE-01  # 只跑一条
node eval/run-eval.js --repeat=8      # 同一条重复跑 8 次，测稳定性
node eval/judge-selftest.js           # 验证裁判本身是否可靠
```

评测会真实调用模型、走真实的系统提示词和状态机，不是文本比对。结果写入 `eval/report.md`。

> 跑评测同样需要 `.env` 里的 API Key。

## 技术说明

### 生成链路

```
玩家输入
  → 规则层判断是否触碰确定性红线（触碰则直接短路，不消耗 API 调用）
  → 组装上下文（角色设定 + 对话历史 + 信任度 + 已解锁线索 + 玩家记忆）
  → 模型生成回复，并在末尾自评一个信任度变化值
  → 代码层剥离标签、钳制数值、过输出红线
  → 结算：更新信任度、判定线索、记录证词
```

### 三层内容门控

| 层 | 职责 | 特点 |
|---|---|---|
| 提示词约束 | 按信任度分级规定可以说什么、绝不说什么 | 覆盖面广，但不保证遵守 |
| 输入硬过滤 | 确定性红线直接短路 | 完全可控，代价是僵硬 |
| 输出过滤 | 模型越过红线时拦下并替换 | 兜底，只拦强信号以免误伤 |

### 两个容易踩的坑

**`presence_penalty` 必须为 0。** 它惩罚"已经出现过的 token"，而 `[trust:+N]` 是每轮逐字重复的固定格式，会被系统性地挤掉——症状是短会话完全正常、第 8 轮之后标签偶发丢失，极难归因。

**主动台词也要写进对话历史。** 线索反应、阈值触发、关键词反应这三类台词是脚本控制的，很容易忘记把它们记进 history，结果 NPC 对自己刚说过的话完全失忆。

## 已知限制

- **只接入了一个 NPC。** 另外两个角色的设定已完成，但对话链路尚未接入；界面上点击他们会给出叙事反馈而不是死块。
- **单轮投票。** 只做第一轮淘汰，没有后续轮次。
- **评测的维度划分偏系统视角。** 「协议遵循」「异常输入」这类是开发者的检查项，不是玩家能感知的体验。`eval/personas.json` 是下一轮重构的起点。
- **像素字体依赖外部服务。** 离线环境下会回退到系统字体，见 `assets/README.md`。
- **未实测环境**：手机端与平板布局已做响应式适配，但尚未在真机完整验证。
